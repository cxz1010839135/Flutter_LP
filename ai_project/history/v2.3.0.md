## 寄存器监视「新通讯」开关

用户需求（截图红箭头 + 参考 C# 源码 DScom.cs）：编程页右侧寄存器监视面板加兼容开关，默认开=新通讯方式，关闭=老的；只影响监视面板读取，其它功能不动。

DScom.cs 新版协议（逐行核对）：TCP 8088 长连接；发送扁平 JSON（无换行）：`{"command":<数字码>,"data":{...}}`；响应取 `result`（==1 成功）与 `data`；指令码 get_M=1、get_D=3、get_S=130；请求串行（C# lock）；失败断线重连（Re_connect）；**新版协议无 X/Y 指令**（C# 直接 return false）。Flutter 现状=旧版 HTTP 字符串指令（`robot_get_D` 等）。

实现：
- 新增 [ds_tcp_client.dart](../../lib/network/ds_tcp_client.dart)：`DsTcpClient` 单例，dart:io Socket 连 8088（IP 取 `RobotState.connectionHost`），请求串行链、收包按分片累积到可 jsonDecode 为止（防半包）、1.5s 响应超时、2s 连接超时、失败断开下次请求自动重连、连接失败 2s 内快速跳过（防死轮询卡整轮）。
- [monitor_plc_watch_storage.dart](../../lib/features/monitor/monitor_plc_watch_storage.dart)：`MonitorPlcWatchConfig` 新增 `useTcp`（默认 true，旧配置缺字段视为 true）。
- [monitor_plc_watch_panel.dart](../../lib/features/monitor/widgets/monitor_plc_watch_panel.dart)：第一行标题前放开关会遮挡标题（用户反馈），改到第二行工具栏「自动刷新」右侧，带「新通讯」标签与通道小字——当前页签实际走 TCP·8088（主色）/ HTTP（灰），随开关与页签实时切换；`_readEntry` 分流：D/M/S 且开关开走 TCP（指令码 3/1/130），X/Y 或开关关走原 HTTP。

用户已实测确认新协议跑通：netstat 见 `flutter_application_1.exe` 与机器人 192.168.1.14:8088 ESTABLISHED，当日日志零条 `robot_get_*`（HTTP 寄存器轮询已不再发生）。

## 文件管理页交互改进（多轮用户反馈迭代）

- 本地目录路径改**可点击面包屑**：每段可点直接跳层（同右侧驱控目录样式），当前层主色高亮，点盘符段进盘符根；「此电脑」磁盘列表态保持原样。
- 左右分栏**中间分界线可拖拽**（同驱动器参数页分割交互：悬停左右箭头光标 + 中央把手）：初版卡顿根因=拖动状态变量写在 LayoutBuilder 闭包里，每帧重绘后被重置导致手势失效；改实例字段后连续跟手。占比范围 10%~90%。
- 「一键备份/恢复」与右侧「上传到驱控/下载到本地」**同尺寸**（初版平分撑满 → 改自然宽度后瘪小；主按钮样式补水平 24px 内边距解决）；第二排按钮同样自然宽度靠左，右侧两按钮保持贴右。
- 第二排新增**「安装目录」「日志目录」按钮**（仅 Windows，同款描边样式）：explorer 直达 `RobotPaths.installRoot()` / `RobotPaths.logsDir()`；日志目录自动定位正确位置（Program Files 只读安装时回退 `%LOCALAPPDATA%\Lingpeng\LPRobot\logs`）。

## 运行日志 UTF-8 BOM

用户反馈记事本打开日志乱码：日志文件原为 UTF-8 无 BOM，老记事本按 ANSI（GBK）读。修改 [app_logger.dart](../../lib/core/app_logger.dart)：新日志文件创建时写入 BOM 头。仅对新建文件生效（当天已存在文件需删后重开程序或等次日）。

## 安装器修复：裸机 VCRUNTIME140_1.dll 缺失

客户裸机安装 2.1.9 报「LpWebView2Repair.exe - 系统错误：找不到 VCRUNTIME140_1.dll」，安装中断。

根因：[installer/webview2_repair/CMakeLists.txt](../../installer/webview2_repair/CMakeLists.txt) 写了 `set(CMAKE_MSVC_RUNTIME_LIBRARY "MultiThreaded")` 但放在 `add_executable` 之后——target 创建时已按默认值 /MD 初始化，设置无效，工具始终动态链接 VC 运行库。

修复：设置移到 `add_executable` 之前（`MultiThreaded$<$<CONFIG:Debug>:Debug>`）。验证：重新编译后 PE 内无 VCRUNTIME140_1/140、MSVCP140、api-ms-win-crt 依赖，裸机可直接运行。

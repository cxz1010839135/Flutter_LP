# v2.3.1（2026-11-25）

## 主题：Blockly 编程页「保存卡死」根治 + 错误列表定位

## 背景

用户导入含错误块的工程（ytg11 10.28.xml，4274 块），点「返回 → 确定」保存时界面永远停在确认框（CPU 空闲、无日志、无提示），无法保存。

## 根因链（诊断弹窗逐层命中）

1. 工程含语法错误块（红色警告），编译失败进入失败分支
2. 失败分支回调里残留坏代码 `node.getRowElement()`（`node` 变量不存在，旁边同款行早已注释、这两行漏了）→ 抛 `ReferenceError` → 回调断裂 → 确认框永不关闭
3. 备注块 `math_variableNotes` 在 LLRobot 生成器未注册生成规则 → 一编译就抛异常，被当成错误块标红
4. `UILLRobot.confirm` 回调先执行后关窗：回调同步抛异常 → 弹窗留在屏幕上（「卡在确定界面」的直接表现）

## 跳转定位踩坑记录（重要教训）

错误列表定位历经 5 版：自研坐标换算（两次）→ 闭环校准 → 直控 scrollX+translate → 照抄搜索快照坐标 → **最终版=搜索参照系+实时采集**。前几版反复偏移的真相：

- `ScrollbarPair.set` 换算链用的 `ratio_` 是 resize 时缓存旧值，不可靠（时准时不准的根源）
- 落点公式实为 `参照点(head_xy) − 内容包围盒左上角 + 视口中心`：搜索的 head_xy 遍历全部块维护（最小 x + 首个顶层块 y）≈ 包围盒左上角 → 落点视口正中；错误列表若只取错误块自身坐标做参照 → 落点 = 中心 + 程序深度偏移 → 恒向右下偏
- 展开折叠块会推移布局 → 坐标快照失效 → 必须**先展开、后实时采集**

最终规则：凡复用搜索定位，必须照抄其**采集规则**（含 head_xy 参照系）+ **实时坐标**，不要自研坐标换算。
